# 来财 · 策略回测中心设计方案 v1.0

> **目标**：在协作面板前端提供用户自主回测能力 — 调参、选数据、一键运行、结果按会话归档管理。

---

## 一、现状梳理

### 1.1 当前工作流（手动）

```
用户 CLI 跑 double_top_backtest.py → experiment.json
→ 同步到 backend/data/experiments/
→ 前端被动读列表展示
```

痛点：
- 回测只能命令行触发，非技术用户无法操作
- 参数调整需要改代码或传 CLI 参数，不直观
- 实验产出后只能按时间戳排列在扁平列表中，缺乏分组管理
- 历史对比需要逐个点开查看，效率低

### 1.2 已有基础设施

| 组件 | 说明 | 可复用 |
|------|------|--------|
| `double_top_backtest.py` | 核心回测引擎，纯 pandas/numpy | ✅ 直接 import |
| `emit_experiment.py` | 结果 → experiment.json 适配器 | ✅ 直接 import |
| `build_chart.py` | 为每笔交易生成 K 线复盘图 | ✅ 直接 import |
| `market-data/exports/D1/` | 已有 38+ 品种的日线 K 线 JSON | ✅ 作为数据源 |
| `report_loader.py` | 扫描 experiments 目录 | ✅ 扩展 |
| FastAPI + SQLite | 后端框架和数据库 | ✅ 扩展 |
| Alpine.js + ECharts | 前端框架 | ✅ 扩展 |

## 二、策略可变参数全景

### 2.1 双峰左侧做空策略 — 完整参数表

| 参数名 | 类型 | 默认值 | 建议范围 | 含义 | 敏感度 |
|--------|------|--------|----------|------|--------|
| **核心策略参数** | | | | | |
| `bandwidth_min` | float | 0.14 | 0.10 – 0.25 | 布林带带宽最低要求（扩张期阈值），越大要求越严格 | ⭐⭐⭐ |
| `zone_lower` | float | 0.99 | 0.95 – 1.00 | 左峰区域下界 = H_left × zone_lower，控制入场价格容忍度 | ⭐⭐ |
| `zone_upper` | float | 1.02 | 1.00 – 1.05 | 左峰区域上界 = H_left × zone_upper，允许略高于左峰入场 | ⭐⭐ |
| `tilt_threshold` | float | 0.008 | 0.003 – 0.020 | 布林带平行度阈值，total_tilt < 此值才判定水平 | ⭐⭐⭐ |
| `left_peak_lookback` | int | 30 | 15 – 60 | 左峰最大回溯天数（安全阀，防止过老的峰） | ⭐ |
| `max_holding_days` | int | 20 | 10 – 60 | 最大持仓天数（超时强制平仓，0 = 不限制） | ⭐⭐ |
| **布林带参数** | | | | | |
| `bb_period` | int | 20 | 10 – 30 | 布林带计算周期（天数） | ⭐⭐ |
| `bb_std` | float | 2.0 | 1.5 – 3.0 | 标准差倍数 | ⭐⭐ |
| `bb_ddof` | int | 1 | 0 – 1 | 标准差自由度（1=样本标准差，0=总体标准差） | ⭐ |
| **资金管理参数** | | | | | |
| `fee_rate` | float | 0.0001 | 0.00005 – 0.0003 | 手续费率（双边各收一次） | ⭐ |
| `max_per_trade` | int | 1,000,000 | 500K – 2M | 单笔最大保证金 | ⭐ |
| `max_total_exposure` | int | 6,000,000 | 2M – 10M | 跨品种总敞口上限 | ⭐ |
| `total_capital` | int | 10,000,000 | — | 总资金（仅展示用，不参与计算） | — |

### 2.2 参数分组逻辑（前端展示用）

```
📈 入场条件参数
   ├── bandwidth_min      带宽阈值
   ├── tilt_threshold     平行度阈值
   ├── zone_lower         左峰区域下界
   ├── zone_upper         左峰区域上界
   └── left_peak_lookback 左峰回溯天数

📊 布林带参数
   ├── bb_period          计算周期
   ├── bb_std             标准差倍数
   └── bb_ddof            自由度

⏱️ 风控参数
   ├── max_holding_days   最大持仓天数
   └── fee_rate           手续费率

💰 资金管理
   ├── max_per_trade      单笔上限
   ├── max_total_exposure 总敞口上限
   └── total_capital      总资金（展示）
```

### 2.3 数据选择维度

| 维度 | 来源 | 说明 |

| 品种（可多选） | `market-data/exports/D1/*_kline.json` | 38+ 品种可选 |

## 三、需求分析

### 3.1 用户故事

**US-1：参数调优回测**
> 作为策略研究者，我希望在网页上调整策略参数，选择目标品种，点击按钮就能看到回测结果，而不需要打开终端改代码。

**US-2：会话式管理**
> 作为策略研究者，我希望把一组相关的回测放在同一个「测试会话」下，比如「带宽敏感度分析」「zone 区域调优」等，方便后续定位和横向对比。

**US-3：参数对比**
> 作为策略研究者，我希望在同一会话中，不同参数配置的回测结果能并排对比，快速找到最优参数组合。

**US-4：结果复用**
> 作为策略研究者，我希望回测结果保留完整的参数快照和交易明细，随时可以回到历史会话查看。

### 3.2 功能边界

| 范围内 ✅ | 范围外 ❌ |
|-----------|-----------|
| 前端调参表单（分组展示 + 范围限制） | 自动参数优化（网格搜索/遗传算法） |
| 选择品种/合约进行回测 | 实盘交易 |
| 一键执行回测并查看报告 | 多策略同时回测 |
| 测试会话的创建/命名/管理 | 用户权限管理（仍是两人共用） |
| 会话内多回测记录的管理和对比 | 品种数据增删（走现有 market-data 管道） |
| 完整参数快照保存 | 参数模板的导入导出（可后续迭代） |

### 4.2 数据模型（SQLite 新增表）

```sql
-- 测试会话
CREATE TABLE backtest_session (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,                    -- 会话名称，如「带宽敏感度分析」
    description TEXT DEFAULT '',                  -- 会话描述/目的
    strategy_type TEXT DEFAULT 'double_top_short',-- 策略类型
    status      TEXT DEFAULT 'active',            -- active / archived
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 回测记录（每条关联一个会话 + 一个 experiment.json）
CREATE TABLE backtest_record (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id      INTEGER NOT NULL REFERENCES backtest_session(id),
    experiment_id   TEXT NOT NULL,                -- experiment.json 的 ID/目录名
    label           TEXT DEFAULT '',              -- 用户给这次回测的标注，如「bw=0.18」
    params_json     TEXT NOT NULL,                -- 参数快照 JSON
    -- 冗余 summary 字段（方便列表快速展示，不必每次读 JSON）
    total_pnl       REAL,
    win_rate        REAL,
    total_trades    INTEGER,
    max_drawdown    REAL,
    total_return_rate REAL,
    status          TEXT DEFAULT 'completed',     -- running / completed / failed
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_backtest_session ON backtest_record(session_id);
```

```
backend/data/experiments/
├── _sessions/                           ← 会话化回测目录
│   ├── session_001_带宽敏感度分析/

│       └── ...

设计考量：
- 旧的扁平实验目录**不迁移不动**，仍出现在「全部报告」列表
- 新的会话化回测产出在 `_sessions/<session>/` 子目录下
- `report_loader.py` 扩展为递归扫描，旧的扁平和新的会话化兼容
- 每条回测记录的 `experiment_id` 存的是相对于 experiments 根的路径

## 五、API 设计

```
GET /api/backtest/strategy-params
```

返回当前策略所有可调参数的元信息（分组、类型、范围、默认值），前端据此动态渲染参数表单。

  "groups": [

      "icon": "📈",
      "params": [
        {
          "key": "bandwidth_min",

          "max": 0.25,
          "step": 0.01,
          "description": "布林带带宽最低要求，越大越严格",
          "sensitivity": "high"

        ...

    ...

```

### 5.2 可用数据集

```
GET /api/backtest/datasets
```

扫描 `market-data/exports/D1/`，返回所有可回测的品种/合约列表。

```json
{
  "data_dir": "D1",
  "instruments": [
    { "id": "ag0", "name": "白银主力", "exchange": "SHFE", "file": "ag0_kline.json" },
    { "id": "rb0", "name": "螺纹钢主力", "exchange": "SHFE", "file": "rb0_kline.json" },
    ...
  ]

```

### 5.3 会话管理

```
GET    /api/backtest/sessions                    → 会话列表
POST   /api/backtest/sessions                    → 创建会话
PATCH  /api/backtest/sessions/{id}               → 更新会话（重命名/描述/归档）
DELETE /api/backtest/sessions/{id}               → 删除会话（连带其下所有回测记录）
```

### 5.4 回测记录管理

```
GET    /api/backtest/sessions/{id}/records       → 会话下的回测记录列表
GET    /api/backtest/records/{id}                → 单条记录详情（= experiment.json）
DELETE /api/backtest/records/{id}                → 删除单条回测记录
```

### 5.5 执行回测（核心）

```
POST /api/backtest/run
```

**请求体：**
```json
{
  "session_id": 1,
  "label": "bw=0.18, zone=1.01",
  "instruments": ["ag0", "rb0", "cu0", "ni0"],
  "params": {
    "bandwidth_min": 0.18,
    "zone_lower": 0.99,
    "zone_upper": 1.01,
    "bb_period": 20,
    "bb_std": 2.0,
    ...
  }
}
```

**执行流程：**
1. 后端读取选中品种的 K 线 JSON
2. 调用 `run_single_backtest()` / `run_all()` 执行回测
3. 调用 `attach_charts()` 生成 K 线复盘图
4. 调用 `emit_experiment()` 输出 experiment.json
5. 在 SQLite 中创建 backtest_record
6. 返回完整的 experiment 数据

**响应体：** 完整的 experiment.json 结构 + record_id

### 5.6 参数对比

```
POST /api/backtest/compare
```

传入多个 record_id，返回对比表格数据（并列展示各回测的 summary 指标 + 参数差异高亮）。

### 7.4 性能与安全考量

| 关注点 | 方案 |
|--------|------|
| 回测耗时 | 当前 38 品种全跑约 2-5 秒；选 3-5 个品种 <1 秒。同步执行可接受。 |
| 并发回测 | v1 同步执行（单用户场景够用）；v2 可引入 BackgroundTasks |
| 路径安全 | 品种 ID 白名单校验（只允许 `exports/D1/` 下存在的文件） |
| 参数校验 | 后端用 strategy_params.py 的 min/max 做范围校验 |
| 磁盘膨胀 | 每个回测 ~100-500KB JSON；提供删除接口；可设置会话上限 |
